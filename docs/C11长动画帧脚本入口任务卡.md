# C11 / E03 长动画帧脚本入口

2026-10-15，接已推送且CI成功的`132665417558fea46a1747b272e624b9a44a326a`。0.94.0运行版本保持，本批独立接续QA格式3，E03仍部分完成、固定25工作包。

## 问题与固定范围

上一批Long Tasks已经能对齐时间并保留上下文，但`self/unknown`没有函数信息。下一步用浏览器支持时的Long Animation Frames保存它实际给出的脚本入口，形成可定位生产字节的新证据，不重复用普通切换签完整资源释放。

本批读取W3C Long Animation Frames工作草案（2026-04-28版）：https://www.w3.org/TR/long-animation-frames/ 。它提供脚本URL、函数名、字符位置、入口类型及窗口归属；这些是部分入口信息，不是完整调用栈或源码映射。当前为草案，只按浏览器实际支持分支记录，不假定所有设备支持。

同源iframe的帧归入同源根文档。因此在QA父页观察长动画帧，另存其时间原点并转换采样窗口；必须明确包含QA自身开销。Long Tasks仍在游戏iframe观察，二者各保留原始指标，不能相加成“总卡顿”。不保留Window对象或私有游戏内存。

## 验收

1. 支持与不支持两个真正QA模块分支；回调、尾队列、窗口外过滤、重复停止及下一轮清空通过。
2. 新格式3原生导出包含帧时长、blockingDuration、renderStart/styleAndLayoutStart、UI时间戳及scripts；复核器兼容历史1/2并验证新字段。
3. 用正常菜单/场景切换产生实际浏览器样本，不注入忙循环、不改游戏时间。若没有脚本信息，记录实际空值，不借示例补造。
4. 若实际获得生产脚本位置，只读对应固定发行文件核字节位置；不能凭入口名推断整个任务唯一根因。
5. 玩家state与155生产发行文件保持，旧850原件及此前迁移证明冻结；新增原件单独登记。
6. 完整检查与必要网页原生证据，更新有限验收，独立提交推送，核远端SHA/CI。最大群战、真实保留对象/GPU和完整调用栈仍开放。
