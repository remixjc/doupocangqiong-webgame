# AI 分批制作与持续迭代手册

适用工程：斗破苍穹 · 异火之路；当前基线：0.1.0 压缩主线 Alpha。

## 执行原则

每批读取当前仓库、开发进度、计划和已有测试，再确定要改变的具体行为。先实现一个可操作流程，随后添加数据与表现。AI 生成的内容必须进入配置和实际运行，不能仅交付按钮、截图或提纲。

当前授权允许自主实现、修复、验证、git commit 和 git push。每个阶段检查通过再推送 main；不强推远端。账号权限、付费服务、正式 IP 授权等外部条件单列，不为绕过外部限制构造替代入口。

执行循环：

1. `git status --short` 和 `git log` 确认已有交付，保护用户改动。
2. 按下表读取相关文件，写下本批验收目标和依赖。
3. 修改规则与类型 → 接入 UI / 画布 → 编写剧情配置 → 更新文档。
4. 用最小有意义的规则测试证明关键不变量；涉及交互则执行浏览器操作。
5. `pnpm run check`，修复失败和阻断问题。
6. 更新开发进度、版本验收、变更记录，标明未测项。
7. 查看差异，`git add` 精确文件，`git commit` 描述实际行为，`git push origin main`。
8. 核对远端 SHA 和 CI，记录真实结果；失败则修复并新增提交。

## 可直接交给后续 AI 的批次任务

基础任务模板：

> 阅读 README、docs/开发进度.md、docs/全周期开发计划.md、docs/版本验收.md 和相关源文件。实现本批指定的可操作行为，保留当前可玩流程和旧存档；不要把资料未知项写成已核验。先完成规则与配置，再接入 UI 和 Phaser。运行 pnpm run check，并通过浏览器完成一条代表性流程。记录实际测试及限制，完成独立 git commit 和 git push，核对远端与 CI。不要仅输出建议或把未实现项标完成。

C1 任务示例：

> 将乌坦城前三章扩展成独立地图：萧家后山、家族测试厅、坊市。提取地图配置，NPC / 交互点 / 碰撞 / 出口使用数据定义；旧 CombatWorld 仍能通过已有回放。新增测试石任务和坊市竞争事件。每章目标至少包含一种有独立规则的剧情操作，保留普通修炼战作为可选资源来源。新增区域进度存档迁移及失败恢复，实玩新手流程后提交推送。

实际拆分为 C1a 与 C1b。C1a 已实现后山、议事院、坊市地图及三种基础事件，文件输入和交接见 [C1 批次任务卡](C1批次任务卡.md)。C1b 保留测试石与竞争事件，按任务卡继续；C1a 完成不等于整个 C1 已完成。

C4 任务示例：

> 为炼药师大会制作多轮赛程和独立计分；纳兰嫣然战采用独立决斗场、招式预警和可读的阶段机制；逃离加玛制作追击路线和出口条件。每种机制先定义成功 / 失败 / 重试规则，避免只是更换普通首领名称。补齐任务与存档测试，核对故事衔接，分三个可审阅提交推送。

C7 任务示例：

> 实现丹界地图和限时药材目标、丹雷生存、三千焱炎火控火试炼、魂殿突袭营救。将药老离队 / 归队作为统一剧情事件，UI 与战斗只能从同一状态判断。通关后异火和支援只授予一次，错误导入不能提前获得。每个专属关卡有浏览器操作证据。

## 新增章节专属机制的工程步骤

1. 内容卡：人物、地点、先后关系、已核验出处、游戏原创部分、避免的剧透。
2. 玩法卡：玩家输入、关键规则、计分 / 通关条件、失败恢复、预期时长。
3. 数据定义：mapId、eventId、任务目标类型、掉落、敌人模式；ID 一经公开存档不得随意复用。
4. 规则先行：纯状态机或固定步长逻辑；渲染层不直接发首通奖励。
5. 接入：交互提示、移动输入、事件结果、目标 UI、暂停和重试。
6. 存档：对新增字段写迁移；分别测试进行中、已完成、重复进入。
7. 验收：正常流程、失败重试、资源不足、防剧透、刷新恢复、奖励幂等。
8. 推送：记录配置和截图，提交范围与实际功能一致。

## 美术和音频制作流程

先建立资源清单：资源 ID、尺寸、锚点、帧数、背景透明规则、色板和来源。当前使用程序图；替换精灵时只改资源映射和动画表现。

人物分批制作待机、跑动、攻击、受击和闪避，再制作 NPC 和首领。先把一套动作接入实际关卡检查缩放、方向、脚底位置和攻击反馈，再扩展其他角色。场景先制作地面 / 碰撞标记 / 建筑 / 植被，逐一核对可通行范围。

AI 图像按统一参考和资源规格生成，保存可追溯源文件；不要直接把动画截图当作精灵。音频先提供程序合成反馈，正式录音另建来源与许可记录。网页本地资源优先，避免外部 CDN 失效导致空白游戏。

## 数值与测试深化

Beta 逐章记录预计时长、药草与金币供需、平均受伤、首领尝试次数和失败后的恢复成本。用测试输入找死锁，用真实玩家验证操作手感。分别调整普通 / 挑战难度，不把剧情模式通关等同于所有难度合格。

设备矩阵：Windows Chrome / Edge，macOS Safari，Android Chrome，iOS Safari；覆盖横竖切换、触控丢失、后台恢复、音频解锁、存储限制、低帧率及长时间游戏。每条记录写真实环境和结果。

## 后续完成定义

- 内容包：至少一个独立场景和专属事件，开场、目标、结果与下一事件衔接完整。
- Beta：真实设备和玩家试玩，核心死锁为零，数据丢失问题修复，难度与输入可用。
- 正式候选：来源记录完整、版本冻结、迁移和回滚演练、部署后验证通过。
- 维护：问题复现 → 测试 → 修复 → 版本说明 → 提交推送 → CI / 站点检查。

首次主线 Alpha 只是可迭代基线。后续大规模内容与资源制作按上述 C 批次推进，不把所有后续生命周期工作写成已经执行。
