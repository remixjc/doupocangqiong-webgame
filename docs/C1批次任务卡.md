# C1 乌坦城内容包

日期：2026-10-11。C1a 已交付；C1b 待执行。总体仍为压缩主线 Alpha。

## C1a 文件与规则

| 文件 | 职责 |
|---|---|
| src/content/maps.ts | 三张独立地图及后续基础关卡，路径、碰撞、资源、敌人和营地 |
| src/content/events.ts | NPC、木桩、立约点、事件阶段及原创说明 |
| src/core/events.ts | 事件纯状态事务，顺序检查、材料扣除与一次货款 |
| src/game/combat.ts | 实际范围与攻击命中、有效闪避、人物与路标交互 |
| src/game/AdventureScene.ts | 地图绘制、木桩反馈、NPC、当前路标高亮 |
| src/ui/StoryEventPanel.tsx | 接取、报价、交付、完成界面 |
| src/core/save.ts | schema 1→2 迁移与严格事件校验 |
| tests/events.test.ts / replay.test.ts / saves.test.ts | 地图可达、事务、旧档及完整主线输入回放 |

后山：E 与药老交谈，接取后在木桩范围使用八极崩并成功闪避。单纯点击接取不完成任务；方向错误、斗气不足、冷却中攻击不推进。

院落：E 与萧战交谈，依序在祖训碑、演武台、出门路交互。乱序不推进；当前点高亮。普通战与采草可选。

坊市：E 与执事接单，42 或 60 金币报价成交，90 金币报价失败且不扣材料。交付灵草两株和魔晶一枚，材料与货款一次结算；不足不部分扣款。章节重返不重领货款。

事件在菜单内暂停；演练、走路、采集与战斗在实际地图中操作。事件保存不重建场景，也不恢复玩家生命。死亡和休整保留事件阶段。

旧存档：保持已有首领 / 首通记录和所有资源；旧前三章未通过首领时需要补做事件。已通过者迁移为事件完成，不发新货款。保存新格式时保留上一份恢复副本；旧手动档在读取时迁移。

## C1b 下一批详细计划

1. 补齐内容卡：成人礼测试石及坊市竞争的先后关系、人物、原创机制说明。精确小说出处未核验则留空，不把原创操作写为原作事实。
2. 成人礼区域：在现有第三章地图接入测试区域或子地图，定义入口、测试石位置与回程。保留供货已完成记录。
3. 测试石机制：准备→三次控气操作→显示游戏评估结果→完成；低分可重试，无材料损失，不直接改变原著境界。明确玩家按键、反馈、成功阈值与重试方式。
4. 坊市竞争：加入两条有不同成本 / 收益的订单策略或竞争交互，不仅是不同金额按钮。缺料可采集 / 购买；失败可恢复；首次奖励幂等。
5. 多事件进度：目前每章仅一个固定事件。扩展为稳定 eventId 的进度表，保留已发布事件 ID，设计 schema 2 进行中 / 已完成→新结构迁移。
6. 原子奖励：测试结果、支线奖励、主线门槛从同一规则层计算；UI 与场景不能各发一份奖励。
7. 验证：所有入口和交互点可达；低分 / 失败 / 乱序 / 缺料 / 重入 / 刷新可恢复；0.1.0 和 0.2.0 存档保持通关与货币。
8. 完整回放：28 章测试玩家通过实际控气输入与竞争选择，再使用真实浏览器完成新事件和章节结算。
9. 节奏评估：记录实际试玩时长与新手反馈，评估 20 分钟闭环目标。自动模拟时长不作为玩家体验结论。
10. 更新版本、进度、来源状态、截图与验收；运行 pnpm run check；Git 独立提交推送，核对远端提交与 CI。
